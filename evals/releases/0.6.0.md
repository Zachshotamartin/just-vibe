# v0.6.0 command depth and repeated evaluations

This release revises 27 command contracts and strengthens shared execution guidance. Changes replace repeated descriptions with concrete ownership, timing, failure, recovery and verification decisions. The [depth review](../../docs/command-quality.md#focused-depth-review) lists the commands and what changed. The inventory remains 215 skill names, 212 canonical workflows and 112 profiles.

## What quality and convenience mean here

Output quality and convenience are the product goals. We can check behavior, regression sensitivity and preserved Git state against explicit requirements. Whether the agent made helpful architectural choices, explained the result well or saved the user effort requires contextual review and real use. These results do not produce an overall product ranking.

The trials supplied complete written contracts. They therefore removed much of the context preparation and discovery burden that a toolkit should help with. No participating users rated the experience, and no user-preference or convenience scores were collected. Zero interventions means the protocol supplied none; it does not mean the agent never needed clarification. The [contextual review guide](../../docs/command-quality.md#output-quality-and-convenience) covers task fit, maintainability, clarity, discovery, correction burden and defaults, with concrete evidence rather than a composite score.

The revised contracts aim to make useful decisions explicit: distinguish one caller's cancellation from shared cache work, preserve partially staged edits during a commit, and select historical feature revisions before applying time windows. These are reviewed instruction improvements. Their effect on everyday convenience has not been measured.

## Original controlled comparison

The original study ran 32 fresh native CLI trials: four newly authored multi-file repositories × four instruction arms × two repetitions. It compared just-vibe v0.5.0 at `8ed8fcb5b2c690dcff2409268c1d4e3079f59823` with a plain-agent baseline, selected task profiles and matched [ECC instructions](https://github.com/affaan-m/ECC/tree/934195f955cf0da847d59fcd6f68856bce112d8b). All entry points, profiles, permissions and limits are in the [registered protocol](../benchmark/README.md).

| Repository task | Main behavior exercised | Selected profile |
| --- | --- | --- |
| Async cache | Tenant identity, coalescing, independent cancellation, TTL, generation invalidation and view disposal | Frontend engineer |
| Local ledger | Atomic transfers, exact validation, replay/conflict semantics, caller transaction ownership and contention | Backend engineer |
| Temporal ML data | Visible revisions, time windows, label maturity, training-only transforms and unknown outcomes | Machine learning engineer |
| Scoped Git commit | Fix and tests committed while preserving unrelated same-file staged/unstaged changes | Senior software engineer |

All runs requested `gpt-6-astra` with medium reasoning through isolated Codex CLI 0.155.1. The macOS arm64 host used Node 26.7.0, Python 3.9.6 and SQLite 3.51.0. Order was shuffled with seed 5192026, concurrency capped at two and each agent limited to 240 seconds. User config/rules, host skill discovery, plugins, hooks, apps, web and subagents were disabled; the skill-discovery flag is experimental. No user replies were supplied during a trial.

| Instructions | Passed bounded checks |
| --- | ---: |
| Plain agent | 8/8 |
| just-vibe, profiles off | 8/8 |
| just-vibe, selected profile | 8/8 |
| Matched ECC guides | 8/8 |

Every arm passed all eight assigned trials under the final scorer. Both conditions also passed in all eight paired profile comparisons. These checks did not distinguish the instruction arms. They do **not** show that the products are equal, that just-vibe beats ECC, or that profiles improve coding judgment. See the [32 per-trial results](0.6.0-before-results.json) for assertions, paired outcomes, earlier scores and evidence hashes.

## Evaluator audit and retained results

Final results use scorer version 3. Known-correct controls pass and seeded defects fail. The scorer verifies protected inputs, executable behavior, meaningful regression sensitivity, completion and—in the Git case—the committed implementation and tests independently of the mixed worktree.

The initial scorer misclassified some regression failures: Node's default reporter withheld assertion details before later hangs, and Python behavior exceptions or completed assertions before a later hang were not consistently retained. Streaming failure evidence fixes those classifications. A timeout without completed behavior evidence, a setup-only failure or a successful mutant run still does not establish regression sensitivity. The Git grader was strengthened to execute the committed tree, and the evaluator's final SQLite observer connection now closes before temporary-file cleanup on Windows. These changes preserve the original task requirements and behavior assertions.

10 of the original 32 outcome labels changed between scorer versions 1 and 3. Original and intermediate grades, failed attempts and raw workspaces are retained; no model output was repaired or replaced during rescoring. Both original and final scorer hashes are recorded. Two excluded setup pilots are documented in the protocol: the first exposed Git metadata write protection, and both initially inferred an incorrect default without an explicit README reference in the task. The registered task gave every arm that reference. An unexecuted v0.6 preparation predating the Windows cleanup fix was retained separately and contributes no trial results.

## Output review

All 40 final answers were read alongside artifact results; recorded actions were checked for unsupported claims and scope issues. In the eight revised-command answers, each named the repair and local verification. The ML answers explicitly avoided claiming a measured model-score improvement; the ledger answers distinguished local SQLite checks from process-crash or production-reliability testing. The Git answers identified the local commit and preservation of unrelated work, which the grader independently checked.

Those are useful examples of appropriately bounded reporting. They are not blind ratings of maintainability or user satisfaction, and we did not score every sentence or independently audit every internal action. No qualitative winner is claimed. A practical follow-up would compare ordinary starting briefs in real repositories, review anonymized outputs where feasible, and record what users had to clarify, correct or look up. Different users and tasks may prefer different workflows.

## Scope and further evidence

The four tasks load 11 distinct workflows in bundles and exercise four of the 112 profiles. They do not establish standalone success rates for each command or expertise for every role. The other command revisions have instruction review plus structural, generation and packaging validation; existing per-command historical labels are not inflated by this bundled study.

These are authored laboratory repositories with explicit contracts, not third-party production repositories. The ECC arm supplies matched skill/agent documents, not its complete installed hooks, memory and integrations. Fresh agent contexts and restricted prompts reduce contamination; the filesystem read boundary is not hardened. Public fixtures also cease to be a durable blind benchmark. Recorded actions, final reports and artifacts were reviewed, but an absent event cannot prove an unobserved action never occurred.

Further evidence should include held-out work in real repositories, multiple models, missing/ambiguous-context tasks, browser interaction, authenticated deployment recovery and actual integration environments. No live Vercel deployment, database service, training job or native teaching dialog is claimed here.

## Release validation

Local release checks passed: 107 tests, 106 passed and one Windows-specific skip on macOS, plus release metadata, license, archive-content, link and credential-pattern checks. They exercise catalog generation, workflow/runtime behavior, installation, packaging and evaluator controls. Native Codex and Claude installation lifecycles passed in isolated host configuration on macOS, including repeat setup, doctor, update, uninstall and reinstall. npm, pnpm 10/12 and Yarn archive execution passed, including payload survival after package-cache deletion. These validate delivery and utility behavior; they do not substitute for a user convenience study.

The [GitHub CI history](https://github.com/Zachshotamartin/just-vibe/actions/workflows/ci.yml) records Node 22/24 checks on Ubuntu, macOS and Windows. A Windows evaluator cleanup failure and a macOS cold-start timing assumption in an evaluator test were corrected during this release. Final release preparation checks the exact archive and performs a publication dry run; it does not publish to npm.
