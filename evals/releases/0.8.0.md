# v0.8.0 intent workflows

This source release adds eight concrete workflow families: checkable explicit corrections, inspectable memory, implemented alternatives, requirement-linked evidence, project exercises, recorded ML comparisons, selective task undo and revisitable decisions. It contains 216 skill names / 213 canonical workflows, 112 profiles and 22 packs. Existing commands load focused new guides; undo is a new skill. No dependency, provider login, training, remote mutation or global instruction edit runs on installation.

## Implemented behavior

| Family | Runtime and verified boundaries |
| --- | --- |
| Corrections | Revision/file-hash checked managed instruction blocks, explicit provenance/scope, retirement/history, positive/negative guard controls, current-file checking and stale-rule detection. Text/import scans have declared semantic limits. |
| Memory inspection | Project instruction candidates, overrides, bounded imports, managed-block persistence, duplicate/structured-conflict reporting and fresh attributed host-loading observations. Unknown actual loading remains unknown. |
| Alternatives | Two/three owned Git worktrees with initial edits, equal checks, bounded foreground previews, comparison reports, selected-scope application, an undo record, journal recovery and reviewed cleanup. |
| Evidence | Declared acceptance criteria with actual commands/collectors, file and artifact hashes, remote observation expiry, screenshots and self-contained HTML. Human acceptance requires attributed review and matching file identities. |
| Practice | Separate solution and learner worktrees, runnable seeded mistakes, positive/negative controls, protected tests, progressive hints, actual submissions and opt-in progress. |
| ML | JSON/MLflow/W&B export normalization, bounded binary/regression metrics, row/dataset comparability, small-slice and subgroup regressions, feature metadata parity and temporal coverage/violations. |
| Undo | Scoped before/after ownership, inverse three-way merging, preservation of later nonoverlapping edits, refusal of conflicts/index/revision changes and journal recovery. |
| Decisions | Adopted choices, preserved reasoning/history, watched files, numeric reconsideration triggers, fresh attributed observations and saved reviews. |

The [workflow index](../../plugins/just-vibe/references/intent-workflows.md) links concrete schemas, selection rules, limits and recovery procedures.

## Verification

Local release validation completed with 155 tests: 154 passed, zero failed and one Windows-only skip on macOS. The archive check covered 532 shipped files; the 11 changed/new generated skills also passed the skill validator.

- The runtime suite includes actual filesystem/Git operations, a real preview HTTP process, real CLI stdin/result codes, positive and negative controls, artifact/report creation and extracted archive execution. Regression cases cover stale/missing rules, ownership/path tampering, overlapping edits, binary changes, unchanged starting files edited later, deletion of initially untracked files, protected exercise tests, vacuous controls, changed evidence, ML identity ordering and large regression values.
- Lock/journal tests distinguish dead/live owners, interrupted known file states, unknown concurrent edits and a changed Git branch. No broad reset or forced cleanup is used to pass these cases.
- `npm run release:check` validates catalog generation, matching package/manifests, MIT notices, packaged references, credentials patterns and the complete test suite. Windows-specific assertions are skipped on macOS and run on Windows CI.
- `npm run test:browser -- PROJECT_WITH_PLAYWRIGHT_AND_CHROMIUM` runs a local dialog fixture in real Chromium. Open/close, input, visibility, focus return and text pass; a deliberately wrong title fails with exit 2. The proof path captures eight hashed screenshots, renders all eight in the HTML report and produces a viewport screenshot for visual inspection.
- `npm run test:hosts` passed native Codex and Claude setup/repeat/update/doctor/uninstall/cache execution in isolated macOS configurations, including 216 installed skills. It does not invoke a model or alter normal host configuration.
- `npm run test:package-managers` passed archive execution through npm, pnpm 10.14.0/12.5.1 and Yarn 4.18.0, both host setup previews, and continued operation after package-cache removal.

Runtime fixtures establish the stated helper behavior, not guaranteed host-agent compliance. The new instruction branches have no independent model trials or universal quality score. Previous model/competitor trials remain evidence for their original versions only. Native host hook delivery, global instruction loading, provider access, large-scale ML uncertainty and production rollout are not newly certified by this release.
