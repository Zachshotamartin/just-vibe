# v0.14.0 validation

The release adds language-server navigation and diagnostics, ast-grep structural rules, mutation evidence, worker sandbox levels, a ready queue, MCP elicitation and MCP Apps views, and sends less context per prompt and per tool call. It also contains the 0.13.0 changes, which were prepared but not published to npm. The catalog contains 221 skill names, 218 canonical workflows and 113 profiles.

## Routing

On the same 1,183-request corpus, the expected workflow ranks first for 63% of requests, in the top three for 82%, and is missing from the top ten for 9%, unchanged from 0.13.0. Five-fold cross-validation found no weight change that improved both held-out first choice and absence, so the weights stay hand-set; one targeted fix routes questions about misbehaving code to `debug`.

## Regression and packaging

`npm run release:check` passed on the release tree: validation, 546 tests with 542 passed and 4 platform-specific skips, and the archive check (672 files). The website built 359 pages and its 5 tests passed, and `npm run test:operator-browser` passed three times locally. Pull requests #13, #14 and #15 each passed GitHub Actions on Ubuntu, macOS and Windows with Node 22 and 24, plus the web acceptance check. Three failures on those runs had no code cause. A Windows updater-archive test exceeded its 120-second limit (it takes about 60 seconds on a normal run), so it now has five minutes on Windows. A Windows temporary-folder lock failed one cleanup, so that cleanup now retries. One web acceptance run timed out waiting for a preference to render, while the other run of the same commit passed.

Real tools checked in temporary installs: typescript-language-server 4 with TypeScript 5 and Pyright 1.1 (definition, references and diagnostics), ast-grep 0.51.1 (every rule's positive and negative samples), Stryker 9 through `mutation start` (report narrowed to the changed line), and `sandbox-exec` on macOS (writes outside the worktree and reads of a fake `~/.ssh` key fail with EPERM, inspect workers cannot write the worktree, and a secret environment variable does not reach the worker). A Playwright fixture host loaded both MCP Apps views in a sandboxed iframe and recorded an approval with source `mcp-app`.

The publication procedure reruns release checks and tests the exact archive through npm, pnpm and Yarn before upload. Registry integrity, source commit, hashes and the results of that procedure belong in the separate publication record after they are observed.

## Limits

No live host or model trials were run. Not exercised: real Claude and Codex workers under the `host` and `os` sandbox levels, elicitation in a real Claude Code session, a real bubblewrap run on Linux (only its arguments are tested), MCP Apps in a production host, and `.lsp.json` loading in a live Claude Code session. gopls, rust-analyzer, cargo-mutants and mutmut were not run; their adapters are tested against recorded output.
