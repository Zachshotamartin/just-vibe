# 0.8.0 technical guidance expansion

This follows the original [intent-workflow record](0.8.0.md). Its results apply to the 2026-09-20 technical-guidance source changes; prior native-host, browser and platform observations remain evidence for their recorded revisions.

## Changed surfaces

All 213 canonical workflows now include authored evidence, method, misdiagnosis and result-check instructions. The three aliases inherit the canonical contract. There are seven focused security guides and one language/runtime guide, with explicit routes from general review/security and relevant specialist workflows. Existing 22 pack guides and scenario material remain in use. The generated [coverage inventory](../../docs/technical-coverage.md) accounts for every canonical workflow.

Catalog/schema validation rejects incomplete technical contracts and alias divergence. Validation now checks supporting Markdown transitively inside the plugin and verifies conditional guide inclusion in the npm archive. The package test runs the extracted CLI without relying on this source checkout and checks the security contract's technical fields.

## Local evidence

- `npm run check`: 159 tests, 158 passed, zero failed, one Windows-only skip on macOS.
- `npm run eval:security`: five isolated contract controls accept legitimate/corrected behavior, expose each seeded defect at an assertion and reject a disabling remediation. Cases: tenant authorization, path containment, privileged-field assignment, redirect destination and webhook replay.
- Skill-creator `quick_validate.py`: all 216 entry points passed, using the existing local PyYAML dependency. No global environment changes were needed.
- `node scripts/release-check.mjs`: package metadata, MIT notices, shipped links and credential-pattern checks passed.
- `git diff --check`: passed.

The security controls perform no model calls or network probes. They establish executable fixture sensitivity, not vulnerability-detection quality of the new prompts. The [separate model-review protocol](../security/README.md) retains blind input and safe-arm false-positive checks for a future explicitly requested evaluation. Catalog metadata preserves 23 earlier behavioral records as historical and marks current expanded instructions not-evaluated.

## Release boundaries

No npm publication is performed by these changes. Existing published version information and release authentication requirements remain unchanged. Windows-only execution and a fresh remote matrix are not established by local macOS checks. The earlier GitHub runner billing/spending-limit blocker is recorded in the original release evidence; only a new observed run can clear that uncertainty. Scanner integrations in this expansion are documented host-agent procedures; no scanner is bundled or silently enabled.
