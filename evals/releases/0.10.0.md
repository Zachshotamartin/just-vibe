# v0.10.0 release validation

Version 0.10.0 adds persistent goals, scoped memory, orchestration, reviewed worker changes, session continuity, configuration maintenance, trusted bounded execution, local monitoring, evaluation receipts and an operator board. It includes 219 skill names, 216 canonical workflows, 112 roles, 24 specialist agents, 43 focused methods, 22 connector recipes and 19 adapter targets. See the [changelog](../../CHANGELOG.md) and [runtime operation reference](../../plugins/just-vibe/references/runtime-expansion.md).

The [release review](../../docs/release-review-2026-09-20.md) reproduced twelve defects. The [correction record](../../docs/release-fixes-2026-09-20.md) documents their fixes and regression evidence. The 49-group ECC implementation ledger separates delivered code/methods from partial acceptance; it does not claim universal parity or complete live validation.

## Local verification

On macOS, the reviewed runtime passed 326 tests on Node 22.23.2 and 26.7.0, with one Windows-only skip and zero failures. This includes real process cancellation, installer crash injection, concurrent reconnect/configuration operations, session scope protection and packed-archive upgrade/rollback. Python 3.12.14 provider contract fixtures ran locally. Source generation, archive metadata, MIT notices, links and credential-pattern checks passed.

Native Codex 0.152.0 and Claude Code 2.1.258 installation lifecycles passed in isolated configurations. npm, pnpm 10/12 and Yarn archive installation checks passed, including persistence after package-cache removal. Chromium desktop/mobile operator tests passed with no reported accessibility violations or page errors, including reviewed adapter installation and finished-dispatch retirement. The website built 353 pages on Node 24.21.0 and passed four static checks.

Release preparation reruns the release suite against the versioned clean source, binds an exact tarball to its Git commit and SHA-256, tests that archive through all supported package managers, and performs an npm publication dry run. Publication must be verified separately against registry integrity and fresh-cache execution. A prepared archive is not proof of publication.

The versioned 0.10.0 release check passed on Node 24.21.0: 327 tests passed, one Windows-only skip and zero failures, with 784 archive files inspected. Version-dependent fixtures now read the installed package version. A startup-lock contention regression verifies that service stop waits for transient ownership before acknowledging cancellation; it and the service/workbench regressions passed on Node 22. Release verification also covers ownership disappearing between lock acquisition and inspection: this produces a bounded retry rather than an ENOENT failure. Generated agent files also pass staged whitespace checks.

## Release-specific CI exception

The maintainer requested merging and releasing these reviewed changes, retaining the prior instruction to proceed with local checks because GitHub Actions minutes are unavailable. This waiver applies only to 0.10.0. The normal publisher's successful-CI requirement remains unchanged; no blocked or skipped job is counted as passing.

Full Linux/Windows execution, paid-provider behavior, live activation in every editor, GPU/distributed training, real framework/database/device/cloud scenarios and independent translation review remain unverified. Package checks establish installation and fixture behavior, not universal model adherence or subjective output quality.
