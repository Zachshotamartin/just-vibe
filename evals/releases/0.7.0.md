# v0.7.0 daily workflow improvements

This release implements the seven workstreams identified after the v0.6 review. The inventory remains 215 skill names, 212 canonical workflows, 112 profiles and 22 pack guides. Seventeen existing skill entries change; six scenario guides and the daily workflow reference provide conditional detail. No overall product superiority or measured user preference is claimed.

| Workstream | What changed | Requirements and limits |
| --- | --- | --- |
| Proportionate auto | Quick work keeps brief, scope, profile and verification in conversation; tracked work uses existing validated stages. Escalation carries actual evidence and consumed limits. | The host resolves real scope/effects; strategy heuristics do not enforce permissions or prove agent compliance. |
| Discovery | Small starter catalog, full inventory through --all, contextual ranking, selection reasons, ambiguity and concise human output. | Bounded manifest inspection; JS/Python dependency signals and explicit intent rules, not a semantic model. Saved preferences remain context. |
| Scenario depth | Cookie/OAuth/refresh/recovery authentication; dialog/combobox/date interaction; classical/tensor/distributed training; GitHub/Vercel/migration evidence. | Read only the relevant branch and current provider/framework documentation. New prose was reviewed and packaged, not independently scored as expert behavior for every scenario. |
| Continuity | Explicit preferences, revision-checked notes, named checkpoints and comparison of repository, branch, HEAD, index and bounded content. | Local .just-vibe state. Partial coverage requires revalidation; prior verification/authorization is never restored automatically. |
| Collectors | GitHub PR checks with head/base recheck, Vercel build diagnosis, real browser steps, SQL migration/hash reconciliation. | Installed provider tools and applicable access. Browser requires project Playwright/Chromium; SQL collector does not contact a database. |
| Optional hooks | Configured Stop checks, single-file formatters and bounded continuation summaries; local exact-config trust, overlap prevention, timeouts and deduplication. | Inactive by default. Host hook trust is separate. Configured commands execute local project code; this is not a sandbox. Staged files are skipped; check results become stale if project content changes during execution. |
| Distribution | v0.7 package/manifests, exact-archive preparation, source-commit record and guarded publication command with registry-integrity reconciliation. | Actual publication requires the maintainer's npm login and completed CI. A prepared archive or passing dry run is not a published package. |

## Verification performed

The local release check ran 127 tests: 126 passed and one Windows-specific skip on macOS, plus catalog/generation, archive, license, link and credential-pattern checks.

- Local tests exercise routing, revisions and stale checkpoints, path escapes, large-file coverage, provider failures/pending/stale identity, migration drift, browser cleanup, command time/output limits, hook trust changes, partial staging, overlap, deduplication and checks against changing source.
- A real hook entry-point test runs an actual failing local check and verifies its advisory output and retained exit status. No fabricated model trial is counted as hook verification.
- An isolated Chromium test runs the public CLI against a local HTTP fixture: dialog open/close, visible/hidden states, input, text and focus return. A deliberately wrong title fails with exit 2. Reproduce with `npm run test:browser -- PROJECT_WITH_PLAYWRIGHT_AND_CHROMIUM`; the script installs nothing.
- A live, read-only GitHub PR observation resolved identity and retained both successful and failing checks. This validates collection, not the quality of that repository. Stale-head and authentication failures are also covered through deterministic provider fixtures.
- Installed Vercel inspect options were checked; metadata/error/timeout behavior is covered through fixtures. No supplied deployment target was available for a live deployment test, and no deployment was created.
- Native Codex and Claude installation lifecycles passed using isolated configuration on macOS with the v0.7 payload. This establishes installation, updates, inventory and cached runtime execution. It does not establish native hook-event delivery/trust or browser behavior on every host/OS.
- Package tests execute the extracted archive, including the new project and hook-status utilities. Release preparation separately executes its exact archive through npm, pnpm and Yarn and performs an npm publication dry run.

The [CI history](https://github.com/Zachshotamartin/just-vibe/actions/workflows/ci.yml) records runtime/package checks on Node 22/24 and Ubuntu/macOS/Windows. Provider authentication, real database rollout, training runs and host-native hook trust remain environment-specific. The [v0.6 comparison](0.6.0.md) is historical evidence for those instruction versions; it is not relabeled as a model evaluation of v0.7.
