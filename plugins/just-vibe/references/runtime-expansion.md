# Extended runtime and specialist methods

These capabilities are bundled with just-vibe. They do not require remembering slash commands: normal requests route to relevant workflows and focused methods. Use `methods search`/`methods show` for framework and domain methods, or the host's `workbench_read` tool. Methods contain scope, inputs, procedures, failure cases, examples and primary references; they are instructions for the host agent, not vendor services.

Every CLI family below uses `just-vibe <family> <operation> --root /project --stdin` with one JSON object on stdin. Omit `--stdin` for an operation requiring no payload. Read current revisions before mutation. Persistent records live under `JUST_VIBE_HOME`, scoped by canonical project root. Never paste API keys into payloads.

MCP has three separate surfaces: `workbench_read` for inspection, `workbench_manage` for enabled local writes, and `workbench_execute` only when both writes and worker execution are enabled. Input is `{ "family": "sessions", "operation": "search", "payload": { "query": "migration" } }`. Configuration, runner trust, recurring-job authority, host installation, notifications and package updating remain explicit CLI actions. The tool description lists the permitted operations.

## Inventory, maintenance and behavior

- `inventory scan`: optional `locations:[{root,host,scope,paths}]`. Project locations must remain within the bound project; user locations require user-scope access. Reports declared MCP/LSP/plugins/hooks/permissions and skills, duplicates, conflicts and incomplete parsing. Secrets/arguments are omitted. TOML supports common literal configuration; unsupported constructs are reported, not guessed.
- `inventory preview`: `{id,revision:0,path,reason,location?}`. This previews disabling an entire selected configuration/skill/hook/cache file. `apply`, `restore`, `recover` use `{id,revision,hash}` from the current record. Files are renamed to an adjacent exact backup, never deleted based on age. Intervening edits block restore. `changes` and `show` inspect history. Granular foreign permission editing remains a reviewed host-config operation.
- `portfolio scan|status|record`: third-party skill provenance, duplicate/overlap candidates, broken local links and observed just-vibe usage. `record` needs the current revision and optional locations. Unobserved use is not zero. `review` takes `{revision,skill,hash,verdict,reason,locations?}` with keep/improve/update/retire/merge. `propose` adds `{id,patch}`; `resolve` takes `{revision,id,status,evidence}`. Applying a source amendment is a separate reviewed skill edit; a queue verdict does not silently rewrite third-party content.
- `behavior list|preview|save|toggle|remove`: `save` uses `{revision,rule:{id,event,action,enabled,conditions,message}}`. Events: prompt, command, file, stop, all. Actions: warn, block. Conditions AND together and use field command/path/content/oldContent/prompt/tool, operator contains/notContains/equals/startsWith/endsWith/glob, value and optional caseSensitive. Glob supports `*` and `?`; arbitrary regex/code is not evaluated. Preview with `{rule?,event:{hook_event_name,tool_name,tool_input,prompt}}`.
- `behavior controls|preset`: `{revision,profile:"minimal|standard|strict",disabled?:[...]}`. Features are policy, commit, automation, assistant, health, rules, sessions, mcp-health, notifications. Minimal omits automation/health/notifications. A blocking decision survives failure to record its audit observation; unavailable PreToolUse enforcement state denies the attempted action with a repair message. Strict also requires a successful explicit file-read of current contents before observed edits to existing files. Shell reads/edits cannot be comprehensively enforced; this is a hook guardrail, not a sandbox. Stop rules interrupt once per event.
- `mcp-health status|observe|probe|reconnect|recover`: refresh inventory, then pass `{key,configHash,revision,locations?}`. Observe adds actual `outcome:"success|failure"` and optional failure text. Probe makes a bounded credential-free GET; stdio requires the real host. Reconnect adds `runner,runnerHash` for an explicitly trusted command. Reconnect reserves its attempt before execution; concurrent attempts cannot repeat the command. An interrupted reservation requires `recover` with the current revision and a reason after inspecting the actual effects; recovery requires a dead owner process and marks the attempt inconclusive without executing it. Pending attempts are never discarded to meet the 100-server retention bound. Backoff never replays a failed tool call. Reachable does not mean authenticated.
- `ioc import`: `{revision,feed:{id,source,retrievedAt,expiresAt,advisories:[{id,ecosystem,package,versions,sha256?,reference,reason}]}}`. Exact npm/PyPI/crates.io versions only; HTTPS provenance and bounded expiry required. `scan` accepts `paths` for supported lockfiles and optional sourcePaths for exact SHA-256 indicators. Feed authenticity is independently reviewed; stale/missing feeds remain inconclusive. No dependency code is executed.
- `git-hooks preview|status|install|uninstall|check`: install/uninstall use `{revision,hash}` from preview/status. The repository pre-commit hook works outside coding agents, checks staged secret/conflict indicators, then optional trusted project checks. For pre-push, add `hook:"pre-push",runner,runnerHash` to preview/install. The native hook checks only pushed references equal to the clean current HEAD, runs that explicitly trusted verifier and rechecks source afterward. Other pushed commits require their own checkout. Foreign hooks, custom core.hooksPath and worktree-shared installation are preserved; compose `just-vibe git-hooks check` with your existing manager. Staged checks do not stage files or certify a different dirty working tree.

## Sessions and continuity

`sessions import` takes `{id,revision,host,path,location?,title?,allowUnbound?}`. Supported visible transcript adapters: Claude JSONL, Codex JSONL, OpenCode export JSON and generic visible-message JSON/JSONL. Cross-project metadata is rejected; missing project identity needs explicit allowUnbound. Thinking, reasoning, system/developer messages and tool arguments/results are excluded. Imported text remains untrusted historical data. Replacing an existing record requires access to its original scope; capture/import cannot change that scope. Use a new ID for a different scope.

Imports retain a bounded visible-message window and disclose `truncated`, omitted messages/characters and full-message hashes. The default is the last 160 messages, at most 4,000 characters per message and 128,000 total characters. Exports disclose the same omissions. `window` takes `{id,offset?,limit?,characterOffset?,characterLimit?}` to read another message/text slice from the original source, subject to its unchanged hash and original access scope. Limits are 160 messages and 16,000 characters per message; offsets count visible messages and UTF-16 characters. The original source must remain available.

Use `list|search` with query, host, date prefix, offset and limit. `show|resume|export` use id; export adds format json/markdown. `alias` uses `{revision,id,alias}`; remove with `{revision,alias,remove:true}`. `branch` uses `{id,sourceId,title?}`. `capture` takes `{id,revision,title?,host?,snapshot:{objective,summary,next,blockers,constraints,taskId?}}`. `forget` uses id/revision and removes stored content. PreCompact/SessionEnd hooks save structured recorded-task checkpoints; they do not invent an LLM summary of a transcript. Use the [side-question method](methods/session-aside.md) for interruptions and a host-authored summary.

## Trusted execution, bounded work and monitoring

`runners configure` uses `{id,revision,config:{command:["node","scripts/check.mjs"],inputs:["package-lock.json"],purpose,timeoutMs?,maxBytes?}}`. Inspect `show` or `list`, then `trust` with `{id,revision,hash}`. `run` uses id/hash. Changing declared files invalidates trust; specify all relevant configuration/lock inputs. Hashing direct inputs does not prove all transitive dependencies or environment variables are unchanged. Runner output is bounded/redacted evidence, not instructions. `untrust|remove` require current revision.

`jobs create` uses `{id,revision,kind:"loop|schedule",objective,runner,runnerHash,verifier?,verifierHash?,maxRuns?,maxFailures?,intervalSeconds?,deadline}`. It starts disabled. `enable` requires `{id,revision,enabled:true,reason}` stating recurring execution authority. `tick` runs one due reservation; `run-due` runs at most limit (default 3, max 10). A loop ends on verifier success, limits, repeated failure, deadline or cancellation. A schedule continues only within its explicit bounds. No daemon starts on creation; attach `run-due` to an explicitly configured host scheduler, or use `jobs watch` with `{seconds:60}` for a foreground interval of at most one hour. Limits constrain dispatch attempts and time; arbitrary subprocess/cloud billing is not measured. Configure paid providers with their own spend caps. `cancel` and `resolve` require current revision and reason. Cancellation signals the owned child process group and blocks later runner/verifier dispatch. Deadline and trust are checked again before every dispatch and while execution is active. Effects completed before cancellation cannot be undone automatically. Interrupted running reservations never replay automatically. Inspection must reconcile actual effects before resolution.

`services configure` references a current trusted runner with `{id,revision,runner,hash,durationSeconds}` (5–3600). `start` launches an owned Node supervisor; `show|logs|list` report state and bounded redacted output. `stop` requests the owning supervisor to signal only its child group. Startup rechecks stop requests, deadline and current trust under the same dispatch lock used by stop; an acknowledged stop prevents a later child launch. Stale PIDs are never killed. After inspecting an orphaned process, `recover` with id/revision/reason reconciles a run whose heartbeat has been stale for at least ten seconds; it does not signal the old PID. Stop fully before restart/reconfigure. `available` detects optional tmux/PM2/editor executables but does not install or control their unrelated processes.

`canary configure` takes `{id,revision,targets:[{id,url,status?,contentType?,contains?,sse?,timeoutMs?}],intervalSeconds?,durationSeconds?,notifyRunner?,notifyHash?}`. URLs are credential-free HTTP(S). `sample` makes one bounded GET per target, checks status/type/content or SSE heartbeat, and stores hashes rather than response bodies. `watch` performs a sustained foreground watch (up to one hour); `stop` sets its durable cancellation state, aborts active requests and prevents later targets or notifications from starting. An in-flight sample cannot overwrite the stopped state. Optional notifications run only a separately trusted configured command on meaningful failure/recovery changes. Browser/SSE coverage is limited to the configured targets; configure asset endpoints explicitly. A successful HTTP response is not semantic deployment approval.

## Reviews, tours, graph and evaluations

- `council create`: `{id,revision:0,objective,host:"claude|codex",reviewers:["reviewer","security-reviewer"]}`. Reviewers may alternatively be `{agent,host}` objects for cross-host assessment; model choice follows each configured worker host. `recover` reconciles interrupted preparation against the orchestration record. Creates 2–4 independent inspect-only assignments using existing owned workers. `dispatch|collect|cancel` compose orchestration; enabled worker support is separate. `conclude` takes current revision, synthesis and every `{item,resultHash,verdict:"support|concern|inconclusive",evidence}`. Source changes invalidate the council. Unresolved concerns cannot be averaged into approval.
- `atlas map`: optional paths; lexical imports/symbols with source hashes, explicitly not a compiler-resolved call graph. `create` takes `{id,revision,title,description,steps:[{file,line,description}]}`. `validate|show` report stale hashes and line anchors. `export` returns CodeTour JSON; optional path/revision/expectedHash writes a `.tour` while protecting hand edits.
- `graph save`: `{revision,id,label,kind?,observations:[{text,source}]}`. `link` takes revision/from/to/relation/source. `recall` uses query/id and bounded limit; it is literal retrieval, not embeddings. `pin`, `forget`, `compact` provide retention. `import` takes revision/path/format markdown|jsonl. JSONL rows are `{id,label,text}`. Imports are atomic, source-hashed and duplicate-aware; refresh removes disappeared unpinned nodes and labels retained pinned nodes stale; env/credential files are excluded. Foreign systems should export reviewed visible memory into this format; schedules/tools/permissions are never silently imported.
- `evaluation create`: `{id,revision:0,objective,cases:[{id,runner,hash,criterion}],artifacts:[path]}`. `run` executes trusted checks only against fresh complete source/artifact identities. `show|compare|export|verify-receipt` inspect results/integrity; `judge` requires exact receiptHash, verdict and independent reason. `recover` marks interrupted runs inconclusive. CLI-only `promote` requires id/revision/current receiptHash/channel/reason, fresh passing checks and an accepted independent judgment; it records approval without publishing anything. Self-contained hashes establish byte integrity, not observer authenticity, sandbox isolation or correctness. Use a separately trusted container/VM runner for hostile subjects.
- `usage observe`: `{revision,session,model,at,input,output,cacheRead,cacheWrite}` with real cumulative disjoint host counts. Identical snapshots deduplicate; resets need a new session segment. `pricing` supplies versioned rates per million tokens with model/currency/input/output/cacheRead/cacheWrite/effectiveAt/expiresAt/source. Each observed delta retains an immutable rate snapshot. The first snapshot is explicitly estimated at its observation-time rate; a later delta spanning a price boundary stays unpriced because its time distribution is unknown. Updating prices never reprices recorded segments. Overlapping rate intervals are rejected; legacy cumulative records without segments remain unpriced. `report|export` keep unpriced usage unknown and currencies separate. `advise` is advisory, never switches models or measures quality.

## Operator, connectors and updates

`operator status` combines jobs, workers, claims, inbox, merge-review queue and dispatch records. `claim` uses `{id,revision,owner,paths,ttlSeconds?}`; heartbeat renews the exact owner, release removes it. Overlapping live paths and stale leases are visible. `message|acknowledge` are local coordination records. `queue-merge` binds a worker/resultHash and reason; it does not apply or merge. `request-dispatch` can reference only a locally enabled ready job and deduplicates requestId; dispatch reserves before running. `retire-dispatch` takes id/revision and removes only a finished row from the bounded queue. Durable request/ID tombstones prevent replay after retirement; queued/reserved requests cannot be retired. The local board exposes this action as “Retire finished request.” All writes require current revision. External messaging, automatic team reassignment and unreviewed merging are not implied.

Start the actual local board and offline catalog with `node <plugin>/scripts/operator-server.mjs --root /project`. Open its private fragment-token URL. It binds loopback, validates Host/Origin and token, and allows narrowly scoped local actions. Search covers 219 skill names and 43 focused methods. With explicit `--allow-install`, the board can preview and apply owned project skill-adapter install/update/uninstall operations. Exact previews expire after five minutes, cannot be replayed and reject intervening changes. Native user-level installations and Hermes-home changes stay in the CLI. Remote use requires your authenticated SSH forwarding or equivalent gateway; do not expose the token in shared logs. Stop the process to close it. `telemetry status|events|otlp` returns redacted local observations or OTLP JSON logs without sending them anywhere. The output contains the latest retained observations, not a complete event history. Repeated exports of an unchanged observation have the same ID; a changed status/time produces a new ID while `entityId` keeps the original record identity. Polling can miss intermediate transitions.

`connectors list|show|preview` exposes versioned recipes and current setup boundaries. Some recipes have verified endpoint metadata; others require an explicit endpoint after reading current official documentation. `install|update|doctor|uninstall` manage only owned namespaced entries in Claude/Cursor/OpenCode JSON, preserve foreign settings and detect edits. Codex TOML is a reviewable preview to merge with the host’s configuration interface. Managed writes serialize by shared destination and publish complete files atomically. Interrupted operations recover known old/new hashes after a demonstrably dead lock owner; live owners, foreign-host locks and malformed/legacy ownership are preserved for inspection. Recover a pending shared-fragment operation before another fragment changes that file. Authentication and actual tool discovery remain host operations; no service is claimed installed from its recipe.

`updater check` reads npm metadata. `preview` takes `{id,revision:0,version:<exact>,targets:[...],scope?}` and preserves recorded selections; Claude requires its existing explicit scope. `apply` needs current revision/hash, rechecks release metadata and verifies the downloaded archive’s SHA-512 before running that pinned package’s update with lifecycle scripts disabled. No background update. `show|list` reveal receipts; interrupted application requires resolve plus host doctor inspection, never blind replay. Managed bundle edits block replacement; older bundles without baseline hashes retain a complete recovery copy. `rollback-preview` with id/revision/hash/newId prepares the recorded prior exact version for a separate reviewed apply; differing prior versions require per-target previews.

The optional Python client is `python3 <plugin>/scripts/python/just_vibe_llm.py --provider openai|anthropic|ollama --model <explicit-model>`. Prompt arrives on stdin. It uses separate API environment credentials, bounded requests and visible-text streaming; it never reuses Codex/Claude OAuth. Optional fixed runner tools require both `--tools allowlist.json` and `--allow-tools`, existing Node runner trust, 1–5 bounded rounds and empty model-supplied arguments. Each runner dispatches at most once per invocation. Atlas/AstraFlow or unavailable vendor backends are not invented compatibility claims; use an independently verified provider bridge.

## Validation limits

The implementation ledger separates delivered source from acceptance: each group has named observed checks and remaining requirements. Its hash checker verifies source/accounting consistency; it does not execute those checks. Runtime fixtures, authored methods, browser evidence and live host/provider tests remain distinct. Framework guides do not claim their examples ran on every toolchain. Native hook support follows the current [Codex hooks contract](https://learn.chatgpt.com/docs/hooks) and [Claude hooks contract](https://code.claude.com/docs/en/hooks). Seven additional hosts have documented skill-file adapters; their file ownership lifecycle is testable independently from live host activation. This expansion is not a claim that every ECC internal implementation or commercial backend has been reproduced.

## Additional host contracts

AdaL, CodeBuddy, JoyCode, Kiro, OpenClaw, Pi and Trae have owned skill-file adapters. Kiro additionally supports explicit `--editor-hooks` for v1 PreToolUse/PostToolUse/Stop commands and an always-included steering file. Hook exit status can block PreToolUse; Stop remains informational. Tool names/inputs not normalized by a documented host contract remain unobserved, and legacy Kiro formats are not inferred. See [Kiro hook types](https://kiro.dev/docs/hooks/types/) and [examples](https://kiro.dev/docs/hooks/examples/). These adapter fixtures do not establish live host activation.
